    @Transactional(rollbackFor = {Exception.class, IOException})

 2. EXECUTION

 3. SUCCESS
 commit
 4. ERROR

 ACID Principles:
ACID — bu database transaction’larning to‘g‘ri va ishonchli ishlashini kafolatlaydigan 4 ta qoida. Bank systemlari
(pul o‘tkazish, balans) aynan ACID ustiga quriladi.

Scenario: Bankdan pul o‘tkazish
Ali (100$) → Vali (50$)
Ali 30$ yuboradi

Transaction ichida 2 ta ish bo‘ladi:
1. Ali balance -= 30
2. Vali balance += 30

1. ATOMICITY (hammasi yoki hech narsa)
Ma’nosi:
   Transaction ichidagi hamma amal birga bajariladi yoki umuman bajarilmaydi

Muammo (atomicity bo‘lmasa):
1. Ali dan 30$ yechildi ✔
2. Vali ga qo‘shilmadi  (error bo‘ldi)
Natija:
Pul yo‘qolib ketadi

ACID bilan:
Ali -30
Vali +30
Agar 2-qadamda error bo‘lsa:
ROLLBACK → Ali puli qaytadi

2.  CONSISTENCY (ma’lumot doim to‘g‘ri bo‘lishi)
Ma’nosi:
   DB har doim valid holatda qoladi
   Bank rule:
   Balance never becomes negative (masalan policy bo‘lsa)
Consistency buzilsa:
Ali balance = -50 ❌ (invalid state)

Consistency bilan:
Agar Ali’da yetarli pul bo‘lmasa → transaction fail
DB eski holatda qoladi

3.  ISOLATION (transactionlar bir-biriga halal bermaydi)
Ma’nosi:
 Parallel transactionlar bir-biriga aralashmaydi
 Scenario:
 Ali balance = 100
 2 ta transaction bir vaqtda:
 T1: Ali → Vali (50$)
 T2: Ali → John (60$)

 Isolation bo‘lmasa:
 Ikalasi ham o‘qiydi:
 100$
 Natija:
 -10$ (overspending)

 Isolation bilan:
 T1 commit bo‘ladi
 T2 fail yoki wait qiladi

 4.  DURABILITY (data saqlanib qoladi)
 Ma’nosi:
    Transaction commit bo‘lsa — DB crash bo‘lsa ham yo‘qolmaydi

    Scenario:
    Ali → Vali transfer SUCCESS
    COMMIT bo‘ldi
    Keyin:
    Server o‘chib qoldi

    Durability bilan:
    Data disk / WAL log’da saqlangan
    Restartdan keyin ham mavjud
